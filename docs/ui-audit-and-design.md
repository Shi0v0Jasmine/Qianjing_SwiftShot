# 原版审查与 UI 设计记录

## 输入证据

- 原始前端基线：NoMooncake/Popular-Video-Structure-Transfer-Engine 的 main，3c13312。
- 查看原版首页的浏览器画面、页面语义结构及源代码。
- 旧视频为 Google Drive 上的 Swiftshot demo.mov，播放器显示总长 3:24。观看了首页、约 1:15 的素材选择/分镜操作、约 2:35 的补全片段预览等片段；未逐帧审查全片。
- 使用内置 Image Gen 制作完整分镜工作台概念，再实现为 HTML/CSS/React。概念保存在 design/storyboard-concept.png。

## 审查发现与对应处理

| 原有问题或代码证据 | 用户影响 | 本版处理 |
| --- | --- | --- |
| 首页输入区没有完整示例入口 | 没有素材的人难以开始体验 | 明确“打开完整示例”，附案例预览与来源说明 |
| 首页现有画布没有完成状态说明 | 不知道进入后能看到什么 | 首版集中到一个一致、可重置案例 |
| 原代码包含多类案例文案和演示占位 | 对产品能力及案例连续性容易误解 | 统一朝雾咖啡；预制与真实交互清楚分开 |
| 分镜的信息、素材与结果分散 | 不易理解某个镜头为什么存在 | 每镜显示角色、字幕、时长；右侧显示意图和素材 |
| App 根组件的编辑状态位于内存 | 刷新可能丢失当前工作 | 版本化本地存储与 JSON 项目备份 |
| 原版演示页包含导出占位及旧链路 | 展示可能停在结果之前 | 独立本地 Remotion 导出服务，使用当前编辑数据 |

## 视觉规范

- 背景 #111214；面板 #1b1c20；边界 #30323a。
- 主操作 #fe2c55；正文 #eeeef1；辅助文字 #999da9。
- 缺口采用琥珀色 + 三角符号 + 文字；完成采用绿色 + 勾号 + 文字。
- 字体优先 Microsoft YaHei UI / Microsoft YaHei / PingFang SC；中文优先。
- 标题 24–32px，正文 12–14px，次要提示 10–12px；视频字幕独立放大。
- 面板圆角 6–8px；对话框 12px；边界克制，不堆叠装饰卡片。
- 主布局为左侧 200px 导航、中间工作区、右侧 270px 检查面板。
- 小笔记本将检查面板移到下方；手机采用横向步骤与可横滑分镜。

## 页面职责

1. 输入：定义创作意图，了解示例能展示什么。
2. 解析：解释五段结构的作用，并展示如何适配产品。
3. 分镜：查看整体节奏，编辑字幕、时长、顺序及单镜素材。
4. 补全：找到缺口，用镜头意图评估候选，确认素材齐全。
5. 导出：动态预览当前版本，本机生成并下载 MP4。

## 状态与交互

选中、缺口、完成、保存失败、导出中、导出失败、导出完成、过期导出均有可见反馈。重置弹窗说明后果，支持先备份。焦点样式、跳过导航链接、原生 dialog 和上下移动按钮支持键盘使用。卡片拖动另有按钮替代。

## 与旧视频的继承关系

保留深色界面、玫红品牌、实际操作画面、局部放大和最后展示结果的叙述方式。新版以约 100 秒中文说明压缩信息，删除长时间选择文件和等待服务的过程；不用配音，也不借剪辑速度暗示实时 AI 生成速度。

## 限制

本版是可操作的展示工作台。新演示页面没有实时分析上传视频，也没有自动生成运动视频素材；保留的原版工作流负责后续真实 provider 探索。当前审查属于内部走查，不等同于目标用户访谈或可用性研究。
